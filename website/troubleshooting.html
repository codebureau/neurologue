Ollama is not installed

When Neurologue starts up, it checks whether Ollama is installed. If it isnâ€™t, a setup modal appears automatically with a Download Ollama button.

Click the button to open ollama.ai, install Ollama, then click Check again in the modal.

Ollama is not running

Symptoms: The status bar at the bottom of the library window shows Ollama not running (grey dot). A setup modal also appears on startup if Ollama is installed but not yet started.

Check if Ollama is running

Open a terminal and run:

curl http://127.0.0.1:11434/api/tags

If you get a JSON response listing your models, Ollama is running. If you get a connection error, it's not.

Start Ollama

On Windows, Ollama runs as a system tray application. Look for it in the system tray near the clock. If itâ€™s not there, launch it from the Start menu. Once itâ€™s running, click Check again in the setup modal.

Pull the required models

If Ollama is running but models are missing, the setup modal will appear automatically with a Pull all missing models button. Click it to download each model with a live progress bar.

You can also pull models manually in a terminal:

ollama pull nomic-embed-text
ollama pull phi3:mini

nomic-embed-text is required for embeddings and semantic search. phi3:mini is only needed for theme summaries â€” themes will still be created without it, just without the LLM description.

Changing the embedding or LLM model

Open Settings â†’ Models. The dropdowns are populated from your locally available Ollama models. Choose your preferred models and click Save settings.

Note: Changing the embedding model means existing entries were embedded with the old model. The background worker will re-embed them over time using the new model. During the transition, semantic search results may be inconsistent.

No themes appearing

Cause: Themes require at least 4 entries to have been embedded, and clustering only runs after every 5 new embeddings in the current session.

Check your entry count

The entry count is shown in the top toolbar. You need at least 4 entries captured.

Wait for embeddings

The background worker runs every 10 seconds and processes entries in batches of 5. If you've just started the app with many unembedded entries, it may take a minute or two to embed them all. Embeddings require Ollama to be running.

Watch the Worker indicator in the status bar at the bottom of the window â€” a gold dot labelled Processing (N queued) means embeddings are in progress. Once it turns teal and the themes sidebar auto-refreshes, clustering has completed.

Trigger clustering manually (developer option)

If you have 4+ embedded entries but no themes, open the DevTools console (Ctrl+Shift+I in the library window) and run:

await window.neurologue.triggerClustering()

Semantic search not working

Symptom: A yellow notice appears: "Ollama not available â€” showing text results instead."

This means Ollama was not reachable when you ran the search. The app falls back to text search automatically.

  • Ensure Ollama is running (see above).
  • Ensure the nomic-embed-text model is pulled: ollama list should show it.
  • Try the search again â€” if Ollama just started, it may need a moment to be ready.

Theme summaries show "No summary yet"

This means clustering ran successfully but the LLM summary step couldn't complete. This happens when:

  • phi3:mini is not pulled yet â€” run ollama pull phi3:mini
  • Ollama was unavailable or slow at the time clustering ran â€” summaries will be generated the next time clustering runs

Entries saved but not appearing in library

The timeline refreshes automatically once the background worker has embedded a new entry. If a captured entry is not appearing:

  • Check the Worker indicator in the status bar â€” if it shows Processing, the worker is still running; wait a moment and the timeline will update on its own.
  • Check the entry count in the toolbar â€” it updates whenever the timeline refreshes.
  • If you have an active tag or category filter, or a search query, the new entry may be filtered out. Click the Ã— on each active filter pill (or Clear all) to remove the active filters and confirm the entry is present.

Entry categories not appearing

Cause: Entry categorisation is performed by the LLM (default: phi3:mini) after each entry is embedded. Categories wonâ€™t appear if:

  • Ollama is not running â€” start Ollama and the worker will process unclassified entries on the next tick.
  • phi3:mini (or your configured LLM model) is not pulled â€” run ollama pull phi3:mini.
  • The entry was captured before categorisation was supported and hasnâ€™t been re-processed yet â€” re-embedding the entry will trigger classification.

Once assigned, the category badge appears on the entry card and in the detail panel. You can always set it manually via the category dropdown in the detail panel regardless of Ollama availability.

Hotkey not working

  • Ensure Neurologue is running (check the taskbar or system tray).
  • The hotkey is Ctrl+Shift+Space. Another application may have registered the same combination â€” check for conflicts in your OS keyboard settings or other running apps.

Data location

Neurologue stores all data under your OS user data directory:

OSPath
Windows%APPDATA%\Neurologue\
macOS~/Library/Application Support/Neurologue/
Linux~/.config/Neurologue/

Inside you'll find neurologue.db (SQLite) and vector-store/ (LanceDB).

Do not delete the data folder unless you want to start fresh. There is currently no built-in backup â€” use Export to take snapshots of your data.

No conflicts detected

Cause: Contradiction detection requires at least a few embedded entries sharing a theme or tag, and the scheduled scan may not have run yet.

  • Ensure Ollama is running â€” the LLM is required to evaluate whether a pair of statements is contradictory.
  • Check the scan scope in Settings â†’ Worker. If set to Theme only, entries must share a theme; try switching to Tags also for broader coverage.
  • Click Scan now at the bottom of the Conflicts view to trigger an immediate, unlimited scan rather than waiting for the next scheduled run.
  • The scheduled scan only checks a limited number of pairs per run (default: 15). If you have a large corpus, you may need to run several manual scans or increase the limit in Settings â†’ Worker.
